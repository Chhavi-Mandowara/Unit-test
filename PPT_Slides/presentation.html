What is Unit Testing?

A unit test is a piece of code that:

  • Tests a smallest testable part of your application (a "unit")
  • Runs automatically
  • Verifies that the unit behaves exactly as expected

Testing in Isolation (Mocks, Stubs, Spies)

Why Isolation

  • Real dependencies are slow, flaky, unpredictable
  • APIs, DBs, Kafka → can fail or be unavailable
  • Makes tests non-deterministic
👉 Goal: Test logic, not the world

How it Helps

  • Faster tests (no real calls)
  • Deterministic results (same input → same output)
  • Easier debugging
  • Test edge cases (failures, retries, timeouts)

Tools & Concepts

Mock: Fake implementation
Stub: Predefined response
Spy: Tracks calls
Jest: Built-in support for all above
"If your test depends on real services, it's not a unit test."

Mocks and Stubs

CHARACTERISTICS
MOCKS
STUBS
CHARACTERISTICS
• Break outgoing dependencies (indirect outputs or exit points)
• Represents an exit point in a unit test
• Break incoming dependencies (indirect inputs)
• Provide fake behavior or data into the code under test
PURPOSE
Verifies interactions (was method called?)
Returns controlled data
USE CASES
• You care about side effects
• You care about collaboration
• You only care about return value
• You care about output state
If you assert OUTPUT → it's a Stub
If you assert CALLS → it's a Mock
Contentstack

Stubs

You focus on stubbing return values, not verifying calls.

Common Mistakes with Stubs

  • ❌ Stubbing too much — tests become meaningless
  • ❌ Stubbing internal methods instead of dependencies
  • ❌ Creating complex stub logic

Example: Stub Implementation

function sendNotification(emailService, user) {
  const response = emailService.send(user.email);
  return response === "OK";
}

test("returns true when email is sent", () => {
  const emailStub = {
    send: () => "OK" // fixed response
  };
  
  const result = sendNotification(emailStub, { email: "test@test.com" });
  
  expect(result).toBe(true); // only checking result
});

Mocks

You test: Did this function call the right collaborator in the right way

Common Mistakes with Mocks

  • ❌ Over mocking — tests become meaningless
  • ❌ Testing implementation instead of behavior

Example: Mock Implementation

function processOrder(paymentService, order) {
  paymentService.charge(order.amount);
}

test("charges correct amount", () => {
  const paymentMock = {
    charge: jest.fn()
  };
  
  processOrder(paymentMock, { amount: 100 });
  
  expect(paymentMock.charge).toHaveBeenCalledWith(100); // verifying interaction
});

Testing Async Code

Common Mistakes with Async Tests:

  • ❌ Forgetting to await
  • ❌ Not returning the promise
  • ❌ Mixing callbacks and promises incorrectly
  • ❌ Using real timers when fake timers are better
  • ❌ Not testing error paths
If you don't control async flow, your tests will lie.
